# 存档列表性能优化（2026-10-28）

存档近邻配对先排除 300 秒窗口之外的日期，避免每个列表行重复启动 date 解析全部历史文件；保留精确匹配、300 秒阈值、跨午夜、三种时间戳格式及既有距离优先顺序。文件名提取使用 Bash 内建操作。

列表在一次菜单会话内复用双栈配对和元数据；每个协议的 IP 与地区一次读取。重新打开菜单清空缓存，仍可读取新存档及新内容。分页、快照和空地区回退行为保留。

相同 85 份 IPv6 存档的单次近邻配对，date 启动次数由 86 降至 4。本机 Windows Git Bash 耗时由 16,027 ms 降至 489 ms；Windows 的进程启动成本较高，Linux VPS 的实际耗时改善不能照搬。匹配文件一致。

完整离线回归 70 项通过；修改脚本通过 ShellCheck 与 Bash 语法检查。安装包包含同目录的 install.sh 和 ipqa.sh，解压后运行 `bash install.sh`，安装器优先使用本地脚本；历史数据及配置沿用原有安装流程。没有改动检测核心或检测项目，没有发布 GitHub Release。

## 第二轮：整页批量读取

针对首次打开仍逐行出现的问题，改为先准备当前页，再一次输出完整列表。当前页 JSON 使用一个 jq 进程批量读取，损坏报告独立显示为未知，不阻断后续行。时间索引按页懒加载，仅解析可见日期及 300 秒配对窗口内的 IPv6 日期；按天检索候选，保留精确匹配、跨午夜、DST、不同时间戳格式与相同距离的原有优先顺序。直接输入不在当前页的编号仍使用完整匹配路径。

1,056 份双栈存档、首次展示 15 行的 Windows Git Bash 对比：date 调用 28 → 2 次，jq 调用 15 → 1 次；整页输出逐字一致。本地单次耗时约 10.44 → 2.21 秒，Windows 进程与文件开销较高，此计时不代表 Linux VPS 的固定耗时。分页、缓存、损坏文件隔离、空地区回退、跨午夜及跨页输入编号的测试通过，完整离线回归仍为 70 项。

IPQA 自我更新跟随 main；本轮验证完成后同步该主分支，避免后台自动更新把安装包恢复成缺少优化的旧实现。不关闭自动更新功能，也不发布 GitHub Release。
